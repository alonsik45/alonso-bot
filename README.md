# Интеграция AI-ассистента «Алонс» — что сделано

AI работает через **OpenRouter** (бесплатный уровень), не DeepSeek.

## Структура

```
bot/
├── bot.py              # оригинальный бот + 5 точечных правок (см. ниже)
├── ai/
│   ├── __init__.py     # ask_alons() — точка входа, вызывается из bot.py
│   ├── openrouter.py    # клиент OpenRouter API (httpx), fallback между моделями, обработка ошибок
│   ├── prompt.py        # системный промпт: персона + правила + знания
│   ├── knowledge.py      # BOT KNOWLEDGE — структурированные факты о боте
│   └── memory.py        # история диалога пользователя (в памяти, лимит 10 сообщений)
└── data/
    └── roma_info.json   # ROMA KNOWLEDGE — факты о Роме
```

`github_storage.py` не менялся — он не был предоставлен, интеграция его не затрагивает.

## Что изменилось в bot.py (5 правок, весь остальной код не тронут)

1. Импорт `ai` в начале файла.
2. Переменная окружения `DEEPSEEK_API_KEY`.
3. Проверка ключа в `main()` — если ключа нет, бот **не падает**, просто пишет
   предупреждение в лог и Алонс не будет отвечать (весь остальной функционал бота
   работает как обычно — ТЗ п.26).
4. В `receive_message()`: если пользователь не находится ни в одном "ожидающем" состоянии
   (не пишет вопрос/предложение/вишлист и не является отвечающим админом) — его сообщение
   уходит Алонсу вместо старого текста «❌ Я не понимаю».
5. В `back_to_menu()`: при возврате в главное меню история диалога с Алонсом сбрасывается.

## Переменные окружения

Добавить к уже существующим (`TELEGRAM_BOT_TOKEN`, `ADMIN_CHAT_ID`, `RENDER_EXTERNAL_URL`,
`GITHUB_TOKEN`, `GITHUB_REPO`):

```
OPENROUTER_API_KEY=sk-or-v1-...
```

Необязательно (есть значения по умолчанию):

```
OPENROUTER_MODELS=z-ai/glm-5.2:free,nvidia/nemotron-3-super-120b-a12b:free,google/gemma-4-26b-a4b-it:free,openrouter/free
OPENROUTER_SITE_URL=https://t.me/alonsochbot
OPENROUTER_APP_TITLE=Alons Bot
```

Ключ читается только из окружения, нигде не логируется и не уходит пользователю.

### ⚠️ Важно про бесплатные модели OpenRouter

Каталог `:free`-моделей на OpenRouter регулярно меняется — модели пропадают и появляются
без предупреждения (это официальная особенность бесплатного уровня, не баг; на практике
конкретный ID пропадал из каталога уже через несколько недель, что давало `404 Not Found`).

Кроме того, среди бесплатных моделей попадаются такие, которые ведут себя не как обычный
чат-бот:
- **классификаторы безопасности** (в духе Llama Guard) — вместо ответа возвращают вердикт
  вида `User Safety: safe / Response Safety: safe`;
- **"думающие" reasoning-модели** — иногда вместо чистого ответа возвращают сырой ход
  рассуждений целиком (`Here's a thinking process: 1. Analyze user input...`).

Обе ситуации уже реально случались. Защита от них в `ai/openrouter.py`:
- в каждый запрос передаётся `reasoning: {"exclude": true}` — просит провайдера не
  включать ход рассуждений в ответ (поддерживается большинством моделей, но не всеми
  на 100%);
- если модель всё же обернула рассуждения в `<think>...</think>` — тег вырезается,
  остаётся то, что после него;
- если итоговый текст всё равно похож на служебный вывод (вердикт классификатора или
  нетегированные рассуждения) — бот сам, незаметно для пользователя, пробует следующую
  модель из списка.

Поэтому по умолчанию основной моделью стоит **конкретная проверенная модель**
(не `openrouter/free`). Причина: сам `openrouter/free` — официальный роутер OpenRouter
(https://openrouter.ai/openrouter/free), который на каждый запрос сам подбирает
бесплатную модель, но делает это непредсказуемо — именно он в проде подобрал и
классификатор безопасности, и reasoning-модель без чистого ответа. Поэтому в списке
он стоит последним — как крайний резерв, а не первый выбор.

- Список задан через `OPENROUTER_MODELS` (см. выше) — при необходимости обновите
  переменную в Render, без правки кода и редеплоя из GitHub.
- Актуальный живой список бесплатных моделей: https://openrouter.ai/collections/free-models
- Бесплатный уровень имеет лимиты (обычно ~20 запросов/минуту, 50 запросов/день на
  аккаунт без пополнения баланса, до 1000/день после разового пополнения от $10).
  Для бота с активной аудиторией стоит держать это в уме — при частых 429-ошибках
  весь трафик уйдёт в `FALLBACK_ERROR_TEXT` («нейронная часть задумалась»).

## requirements.txt

Менять не нужно — `httpx` уже указан в вашем файле, OpenRouter API OpenAI-совместим и
вызывается напрямую через httpx (без SDK).

## Как обновлять знания бота

- **Кнопки/команды/разделы бота** — правь `ai/knowledge.py` (структуры `COMMANDS`,
  `MAIN_MENU`, `SECTIONS`). Системный промпт целиком переписывать не нужно.
- **Информация о Роме / расписание** — правь `data/roma_info.json`.
- Изменения применятся при следующем перезапуске процесса (системный промпт собирается
  один раз при старте, в `ai/__init__.py`).

## Чего пока нет (сознательно, по ТЗ — расширения следующих этапов)

- **Голосовые сообщения (ТЗ п.23):** STT-провайдер в ТЗ не указан и его нет в
  requirements.txt, поэтому распознавание не подключено. Точка расширения — функция
  `unsupported_message()` в bot.py: там сейчас голосовые считаются неподдерживаемым типом.
  Когда определитесь с STT-сервисом (например Whisper API), нужно будет: распознать голос →
  передать текст в `ask_alons()` — остальная логика уже готова.
- **Intent-based управление ботом (ТЗ п.24):** Алонс пока только отвечает текстом, не
  открывает разделы бота сам. Архитектура (отдельный `ai/` модуль, чистый `ask_alons()`)
  это не блокирует — при необходимости можно добавить парсинг intent из ответа DeepSeek
  (например через structured output) и вызов существующих функций типа `menu_questions()`.

## Новые команды (последнее обновление)

- **`/setstatus {user_id} {текст статуса}`** — выдать пользователю кастомный статус вручную,
  отключает автоматический пересчёт для него.
- **`/resetstatus {user_id}`** — вернуть автоматический расчёт статуса.
- **`/sms {user_id} {текст}`** — отправить пользователю обычное сообщение от лица бота
  (без пометки "вам пришло сообщение", как в рассылке).
- **`/ban {user_id}`** — забанить: бот полностью игнорирует сообщения и кнопки этого
  пользователя (без уведомления). Список банов сохраняется на GitHub (`banned_users.json`),
  переживает рестарт бота. Новый модуль `moderation.py`.
- **`/unban {user_id}`** — снять бан.

Все команды — только для админов (проверка по `ADMIN_CHAT_ID`, как и остальные админ-команды).

## Автоматический live-таймер + /stop

- Каждый день в **21:00 по мск** бот сам проверяет расписание (`data/roma_info.json`)
  и, если сегодня день стрима, включает "live-режим" — без рассылки пользователям,
  просто меняет внутреннее состояние.
- Пока live-режим включён, `/next` и кнопка «⏰ До стрима» показывают
  "🔴 Стрим уже идёт прямо сейчас!" вместо обратного отсчёта.
- **`/stop`** (только админ) — вручную выключает live-режим. После этого таймер
  сам считает до следующего дня по расписанию.
- Состояние (`is_live`) сохраняется на GitHub (`stream_state.json`), переживает
  перезапуск бота (Render перезапускает процесс при простое).
- Новый модуль: `stream_state.py`.

### ⚠️ Нужно обновить requirements.txt

Автовключение в 21:00 работает через `JobQueue` — это отдельная зависимость
(`APScheduler`), не входящая в `python-telegram-bot[webhooks]` по умолчанию.

Замените первую строку `requirements.txt`:

```
python-telegram-bot[webhooks,job-queue]>=21.0,<23.0
PyGithub==1.58.2
httpx>=0.27.0,<1.0.0
```

Без этого бот всё равно запустится (не упадёт), но в логах будет предупреждение,
и `/next`/кнопка так и будут просто считать до 21:00 сегодня/следующего дня без
автопереключения в live-режим — включать его придётся только вручную (либо позже
добавим отдельную команду типа `/live`, если понадобится).
